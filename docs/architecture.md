# TraceLens｜架构设计

版本：0.6 · 对应 [需求说明书](requirements.md)

## 1. 架构决策

采用 **本地 Node 服务 + 浏览器单页应用 + 内存快照**。通过显式刷新读取项目文档，不接入 vNext Runtime，不复制其 Schema 或状态计算逻辑。

被观察项目只读；项目登记和扫描配置保存到本工具的用户数据目录。快照可重新生成，首版不使用数据库。

固定边界是“文档输入、容错提取、内存快照、显式刷新、被观察项目只读”。下述目录、模块名和接口组织是推荐方案，可按实现需要简化；不为未来兼容提前建设插件体系、通用规则引擎或多层框架。

## 2. 技术选型

| 层次 | 选择 | 用途 |
|---|---|---|
| 服务端 | Node.js、TypeScript、Fastify | 本地文件读取、配置管理及 HTTP API。 |
| 前端 | React、Vite、Tailwind CSS | 单页界面及基础样式。 |
| 文档解析 | unified／remark、yaml、Zod | Markdown 语法树、YAML 读取及工具自身配置校验。 |
| 关联展示 | React Flow | 只读、可点击的局部关系图；首版使用简单分层布局。 |
| 存储与测试 | JSON 文件、内存；Vitest、Playwright | 保存配置、缓存快照，验证解析和核心交互。 |

依赖版本在初始化时核对兼容性并锁定；采用单一包管理器和锁文件，通过 package scripts 统一开发、构建、启动及验证命令。不依赖特定 Shell 才能启动。首版不引入 ORM、消息队列、WebSocket、SSE、图数据库或多包框架。

## 3. 模块与数据流

```text
浏览器：概览 / 任务 / 文档 / 关联（另有独立静态 vNext 使用说明）
                  │ HTTP
本地服务：项目管理 / 刷新调度 / 快照查询
                  │
配置 → 文件扫描 → 文档解析 → 信息提取与关联 → 项目快照
         只读          保留原文与来源            内存
```

| 模块 | 职责 |
|---|---|
| ProjectRegistry | 保存项目绝对路径、文档分类规则和排除规则；完成路径校验。 |
| ProjectSources | 只读 Codex 本机项目登记和服务机器目录元数据，为添加表单提供两种路径入口；不执行项目脚本。 |
| Scanner | 按配置枚举并读取文档，去重，记录缺失、跳过及读取错误。 |
| DocumentNavigation | 读取 Profile、既有文档索引及任务依据，保存分类依据、状态与登记缺口；每次显式刷新重新导航。 |
| Parsers | 通用 Markdown 解析；vNext 文档的轻量字段提取；未知格式退回原文展示。 |
| SnapshotBuilder | 归集任务、清单和文档，解析显式关联，汇总冲突及警告。 |
| SnapshotStore | 按项目保存最近快照及刷新结果；刷新成功后整体替换，避免页面读到半成品。 |
| Web UI | 查询并展示快照；不直接访问文件系统，也不理解 vNext 内部存储。 |

当前任务与当前步骤只取 Profile 的 `workflow_home/CURRENT_TASK.md`（无有效 Profile 时使用默认入口）。历史归档仍可阅读，但不会作为概览的当前来源。生成的 `vnext-task-view` 从 `Current work` 提取 Task 和 Step，不从 Tasks 表推断执行焦点；未明确焦点或入口缺失时保留空状态。这里展示的是文档快照，不查询 Runtime 的实时状态。

当前视图中的 `Adopted plan` 可触发一次有界的显式计划记录读取，再跟随记录中的 `document_ref` 纳入计划文档。该读取允许当前视图直接引用的 records JSON，不遍历历史 records、不执行 Runtime，也不改变扫描配置；用户显式排除规则和路径、文件、字节上限仍生效。步骤编号在已采用计划中必须唯一，点击编号与标题可定位计划文档的同编号章节；章节缺失或有歧义时定位计划记录中的步骤定义并说明原因，引用不可读取时显示诊断。

如果计划没有 `document_ref`，步骤直接定位 JSON 记录中的定义，说明未声明独立计划文档，不将这种内嵌计划格式视为文档缺失。

“vNext 使用说明”为全局静态页，与项目和快照解耦；场景数据、核对版本及提示词保存在工具自身源码，不在线解析上游技能或调用 Runtime。以实际 canonical skill 模板维护内容，复制仅写浏览器剪贴板；不给说明页增加服务端执行接口。维护依据见 [使用说明页](vnext-guide.md)。

建议目录保持简单：

```text
src/
  server/
    registry/   scanner/   parsers/   snapshot/   routes/
  web/
    pages/      components/
  shared/
    types.ts
```

## 4. 最小数据模型

添加项目提供 Codex 快捷选择与服务机器目录选择器。Codex 适配器只读 `$CODEX_HOME/.codex-global-state.json`（未设置时为用户目录下 `.codex`），识别当前 `local-projects` 中的名称及 `rootPaths`，兼容旧版 `electron-saved-workspace-roots` / `electron-workspace-root-labels`，按本机路径去重；不把聊天历史、信任配置或远程／云项目当作已登记本机项目。登记不存在、损坏或格式未知时保留目录入口并提示；这是当前桌面版本的本地格式适配，不依赖运行中的 Codex 或云 API。

目录选择器通过本地服务列出当前目录的直接子目录，支持用户目录、盘符／根目录、上级目录和绝对路径跳转；不是浏览器文件上传控件。两个只读来源接口均使用带会话令牌的 POST，保持 Host / Origin 保护；不暴露任意文件正文或写入能力。跳过符号链接／目录联接；每次最多列出 500 子目录、枚举 10,000 项并报告截断，Codex 登记读取上限 16 MiB。选择后仍显式发现并确认文档范围，注册时再次校验，未确认不扫描。Codex 不可读路径和已添加路径不可快捷选择；配置目录位于项目内的路径不得登记。

| 对象 | 必要内容 |
|---|---|
| ProjectConfig | 项目 ID、名称、绝对路径、文档分类规则、排除规则。 |
| SourceRef | 项目相对路径、章节或行号、扫描时的内容摘要。 |
| Document | 文档 ID、类型、标题、原文、章节及扫描元数据。 |
| Task | 任务 ID／原始编号、标题、文档声明的状态、目标、步骤、清单、引用和来源。 |
| Relation | 起点、终点、关系类型、解析方式、原始引用及来源位置。 |
| ProjectSnapshot | 快照 ID、项目信息、概览、任务、文档、关联、实际扫描配置／范围、警告和扫描起止时间。 |

缺失信息用 `null`、空列表及对应说明表达，不生成推测状态。扫描错误、未记录和确实没有匹配内容必须可区分。任务 ID 必须包含项目范围；相同编号只有在身份明确时才合并，冲突声明保留各自来源。

文档 ID 在相同项目、相同相对路径下保持稳定；章节位置绑定扫描所得原文。概览声明、关系和原文阅读使用同一个快照 ID，避免刷新后从旧任务跳到新版本原文。首版不需要保存多版本历史。

文件选择、读取缓存、文档／任务 ID 和引用目标使用统一的相对路径键：Windows 忽略路径大小写，Linux／macOS 保留大小写；显示仍保留来源路径的写法。不因同一 Windows 文件被不同大小写规则选中而重复读取或生成多个任务。

引用中的 `revision` 仅作为文档声明保存；不将任意版本字符串与当前文件摘要直接比较，也不据此宣称版本一致。

## 5. 扫描与解析

**扫描范围：** 用户配置优先；识别已有 Profile 的已知路径字段辅助发现；默认路径仅作兜底。排除源码依赖、构建产物、`.git` 和二进制内容；`records` 默认排除，可显式允许其中的文档。不执行仓库内任何脚本。

Profile 采用 vNext 现有 `paths.documentation_files` 导航种子与 `paths.workflow_home`，补充可用的 README／文档中心／DOCUMENT_CATALOG。Markdown 索引列表、表格中的明确用途和分类、已知文档类型元数据为分类依据；标题和路径仅给出建议分类，冲突或未知使用 `unclassified`。只在已识别导航入口中解释带用途的反引号路径，不把任意正文中的代码片段当作登记。管理任务的结构化依据和 Markdown 引用、已知 frontmatter `related_docs` 可扩展导航；`status` 和 `superseded_by` 保留声明，不能自动赋予需求权威性。旧分类扩展字段兼容读取，但不是新格式要求。

工具配置增加可选 `autoDiscover`，新登记默认开启，缺失该字段的旧登记保持原手动范围；手动规则覆盖自动分类，排除优先。持久化仅保存模式及手动规则，不固化自动候选。快照保存 `navigation` 登记依据／状态／缺口与 `effectiveRules` 实际范围，原 `config` 保留启动时工具配置。登记入口不可用时使用上次快照的相关路径重新读取正文并明确登记不完整；有效索引更新移除的条目不继承。没有上次快照时如实报告入口失败。

索引中的普通及引用式 Markdown 链接均支持列表、表格和段落。段落链接没有明确分类声明时仅提供建议分类。曾成功读取的可选惯例入口被删除，也按入口不可用处理并保留缺失诊断；从未存在的可选入口不制造错误。用户明确排除入口时不恢复其上次登记范围。

导航与正文共享本次读取缓存，分类来源绑定缓存原文行；不会为展示重新读盘。导航最多 120 次读取、10 MiB、500 登记路径、3 层跳转，每路径最多保留 16 个来源并独立报告截断；正文仍最多 500 文件、单文件 2 MiB、合计 20 MiB，枚举 20,000 项、目录深度 24。规则采用项目相对文件路径或 glob，支持 `*`、`**`、`?` 和花括号；固定跳过依赖、构建、.vnext、journal 与符号链接／目录联接，records 默认排除可显式允许。不执行 Profile 的命令字段。

整理提示词在前端依据当前快照生成，包含维护约定与至多 100 项登记（每项至多 4 个来源，标明省略）；只提供预览和复制。已有文档中心是维护入口，缺少时建议按项目规范建立 `docs/README.md` 导航，不引入 TraceLens 专用权威清单或模型调用。登记核对不计算用户需求完整度，不声称 Runtime 已确认全项目文档。

**解析方式：** 通过 Markdown 语法树提取标题、列表、清单、链接和代码块。vNext 提取器只处理界面需要的已知结构，不要求文档完全符合某个版本。Zod 用于本工具配置和输出边界，不以严格校验整份项目文档作为展示前提。

支持范围以可检查的文档样例为依据，至少涵盖已知标题下的字段／条目、任务编号、步骤与验收清单、Markdown 链接，以及 `### Project documents` 下的 JSON 引用。未知格式回退到原文，不必访问 Runtime 来补齐。结构化引用示例如下，仅为演示值：

```json
{
  "version": 1,
  "sources": [{
    "path": "docs/design/storage.md",
    "section": "恢复策略",
    "revision": "文档声明的版本",
    "purpose": "本任务的设计依据"
  }]
}
```

**关联方式：** 结构化文档引用优先，其次是 Markdown 链接和唯一任务编号提及。项目相对路径按项目根解析，普通 Markdown 相对链接按来源文档目录解析；只有目标位于配置或自动发现范围内才读取正文。范围外目标可进行有界元数据核对。章节匹配失败、目标未纳入扫描或任务编号歧义，均保留原始引用并提示；不猜测最相似章节，不自动补全语义关系。外部链接只保留引用信息，不自动抓取。

首版按来源文件保持独立任务身份，不将同编号文件自动合并；占位模板不产生当前任务。编号提及只解析已收录的任务身份或明确的日期／`TASK-` 编号，不把决策等其他短编号猜成任务。局部图以一层邻居展示，每侧最多显示 6 个节点，完整依据列表不截断；相同方向与类型的多条引用显示为计数边，点击保留每条来源和章节信息。

日期任务编号的 `TASK-YYYYMMDD-NNN` 与 `YYYYMMDD-NNN` 使用同一匹配键，但任务声明与提及原文不改写。同文档自身编号的两种写法不生成自我提及；不同文件声明同一匹配键仍分别保留任务身份，并将相关提及标为歧义。

**容错与一致性：** 单文件失败形成警告，发布其余内容的部分快照；根目录／配置不可用，或匹配文件全部读取失败时，整体失败并保留旧快照。配置有效且正常扫描后零匹配，是带范围说明的空结果，不是读取失败。部分结果不静默混入旧版文件。

每个项目同一时间只运行一次扫描；重复刷新复用当前任务或提示扫描中，不并发覆盖。扫描固定使用启动时的配置；中途配置变化仍标记需刷新。首版不提供跨文件事务快照，扫描期间检测到文件变化时提示重新刷新。设置合理的文件数量、单文件大小和总读取量限制；达到限制要报告扫描不完整，不宣称已读完整项目。

## 6. 接口与持久化

通用发现修复：自动导航支持普通 Markdown 显式链接、已知 vNext `document_kind` / `kind` 及 `path_references` 的 `repo-relative` 路径；根目录与管理目录的可用 `TASKS/` 均参与默认范围。可选目录缺失不视为必需文件缺失。元数据损坏保留原文与诊断，不修复或部分信任错误 YAML。

配置增加 `candidateRoots`（缺省为 `docs`、`TASKS`，空数组停用）与 `includeRecords`（缺省 false），变更纳入配置指纹；旧快照继续保留当时范围。`navigation.inventory` 保存只枚举元数据得到的未登记候选、排除原因及独立的不完整标记。候选不读取正文、不进入登记分类或完整性判断；最多 500 个候选、20,000 枚举项、深度 24，不跟随目录联接。`records` 可显式允许，其余硬排除保持有效。

反引号简写延后到明确引用读取后，在来源目录、项目根及已登记路径中核对唯一目标；示例占位符、歧义或未定位简写不生成必需文件。显式 Markdown 链接严格按来源目录解析。引用目标在范围外时仅执行有界元数据检查，分别记录存在、缺失、排除、示例或未核对状态。每文档来源超过 16 条只截断来源列表，使用独立 info 诊断；读取数、字节、路径和跳转深度各自报告真正的导航限制。

项目文档的修复由对应项目 agent 按项目规范执行；整理提示词携带候选与登记证据，明确候选不等于需要补写。TraceLens 不执行该提示词或写被观察项目。

| 接口 | 行为 |
|---|---|
| `GET /api/projects` | 返回已登记项目。 |
| `POST /api/projects` | 校验并登记目录及扫描配置。 |
| `PATCH /api/projects/:id` | 更新本工具的项目配置；不自动修改项目文件。 |
| `DELETE /api/projects/:id` | 移除登记及内存快照，不删除目录。 |
| `POST /api/projects/:id/refresh` | 显式扫描，返回刷新结果与警告。 |
| `GET /api/projects/:id/snapshot` | 返回最近快照；没有快照时明确返回“尚未扫描”。 |
| `GET /api/projects/:id/documents/:documentId` | 返回该快照收录的文档内容和章节，不接受任意文件路径。 |

前端添加项目后发起首次刷新；之后仅由用户点击刷新触发扫描。快照和文档接口只返回已扫描内容；以快照 ID 校验详情请求，过期时提示客户端重新加载快照，不隐式读盘更新正文。

项目配置保存为用户数据目录中的 `projects.json`，采用临时文件加替换方式写入；移除项目不影响原始文件。配置变更不自动扫描，重启后内存快照为空。明确区分最后一次刷新尝试及当前展示快照，失败不能覆盖旧快照的扫描时间。

启动读取既有登记及每次保存前，均检查工具数据目录不位于任何登记项目内；迁移数据目录导致越界时拒绝启动且保留原登记文件。不以项目目录当前可读作为恢复登记的前提，项目暂时离线或被移动后仍可查看、移除登记；扫描时另行报告目录不可用。

## 7. 本地安全与部署

生产运行时，由同一个 Fastify 服务提供 API 和构建后的前端资源；默认监听 `127.0.0.1`。安装依赖可访问软件源，正常查看本地项目不依赖外网、CDN、外部字体或云账号。开发期前后端可分别启动，由开发代理保持 API 访问方式一致。

校验 Host／Origin，对配置写入及刷新接口提供会话令牌保护，不开放任意跨域访问。读取路径必须属于已登记项目的配置范围，规范化后检查真实路径；首版跳过符号链接／目录联接并提示。

Markdown 禁用原始 HTML 和 MDX 执行，过滤危险链接协议，不自动加载远程资源。不暴露 Shell、任意路径读取或项目文件写入接口。

## 8. 工程与验证原则

实施顺序由开发者根据当前代码和验证结果决定；以可运行的用户操作闭环推进，不以建完目录或组件为完成。模块可在单个代码库内组织，不要求逐项拆包。长期产品和架构决策更新这两份文档，运行说明写入 README，不另建重复需求、固定步骤清单或繁重验收台账。

测试重点：已知／未知文档格式、路径与章节引用、任务编号冲突、单文件失败、整体刷新失败、刷新后增删改、重启后配置保留，以及路径越界和 Markdown 注入。以真实文档样例或明确标注的合成样例做回归，采用足以覆盖行为和风险的检查，不为文案、界面标题或每个提取字段建立重复测试。
