# TraceLens｜需求说明书

版本：0.7 · 标准产品文档、规划及范围化交付阅读

本文件定义产品目标、范围与交付完成标准；[架构设计](architecture.md)定义实现边界与推荐组织。实现细节可在这些边界内自主决定，不得通过删减需求来宣称完成。

## 1. 产品目标

启动本地 Web 服务，添加项目目录后，读取其中的 vNext 管理文档、需求文档、设计文档及规划文档，直观展示项目进展、当前任务和文档之间的关联。

**展示的是文档记录的项目状态，不是 vNext Runtime 的实时状态。** 不调用 vNext API，不还原 Runtime 内部状态，不要求项目修改现有文档格式。

首版默认使用简体中文，面向桌面浏览器和本机开发者，优先支持 Windows 原生运行及含中文、空格的项目路径。目录路径以服务所在操作系统为准，不自动转换 Windows／WSL 路径。

用户应能回答：文档说当前在做什么、已记录哪些成果、下一步有哪些规划，以及当前任务依据哪些需求和设计。不能回答的内容明确保留未知，不用图表补造结论。

## 2. 使用流程

启动服务 → 浏览器打开页面 → 从 Codex 已登记的本机项目快捷选择，或打开服务机器的目录选择器 → 查看自动发现的文档与登记来源，必要时调整高级范围 → 添加并扫描 → 查看任务、来源和登记缺口 → 需要更新时手动刷新。

项目列表和扫描配置在服务重启后保留；移除项目仅删除本工具中的登记，不删除项目文件。

## 3. 功能要求

| 编号 | 功能 | 首版要求 |
|---|---|---|
| R1 | 项目管理 | 添加、切换、移除本地项目；添加支持只读 Codex 已登记本机项目的快捷选择及服务机器目录选择器两种入口；检查路径存在且可读；配置各类文档的路径或匹配规则。 |
| R2 | 文档扫描 | 根据 vNext 既有文档导航和用户补充范围读取 Markdown 与必要的 YAML；展示实际范围、登记来源、分类依据、文档状态、缺失及读取失败项。 |
| R3 | 项目概览 | 汇总文档明确记录的当前任务、状态、步骤、待办、风险和规划；展示最近成功扫描时间。 |
| R4 | 任务浏览 | 展示当前任务及历史任务列表；查看目标、步骤、验收清单、问题及引用文档，字段缺失时保留空缺。 |
| R5 | 文档阅读 | 按管理、需求、设计、规划等类型浏览文档，支持目录导航及定位到引用章节。 |
| R6 | 关联查看 | 展示文档、章节和任务间的显式引用关系；可从任务查引用文档，也可从文档查引用任务。 |
| R7 | 手动刷新 | 点击刷新后重新扫描当前项目；页面展示扫描中、完成、部分成功或失败状态。 |
| R9 | 标准需求 | 用户明确启用 PRODUCT 后，读取 v1/v2 当前登记，按工作副本隔离目标、模块、四种 scope 需求、设计等九类条目；保留正文、坏项、元数据和来源。 |
| R10 | 总体规划 | 显式选择计划，按原数组顺序展示阶段、覆盖、工作项、明确依赖及原定／新增／未知；无计划仍可看完整业务范围。 |
| R11 | 范围化任务关联 | 区分真实 task_id、显示编号、UI 文件身份；展示多任务绑定、角色、工作项、repair 和历史被修复范围，任务页可反查业务条目。 |
| R12 | 报告与依据 | 只沿 assessment_id 选中报告，并列展示对象版本、覆盖、定义摘要、历史可核验性与 pending_sources；明确／推断／已否定关系分别可查。 |
| R8 | vNext 使用说明 | 无项目亦可访问的静态场景指南，说明 canonical skills、模式、提示词与授权边界；支持搜索、筛选、复制，标明核对版本，不执行指令或连接 Runtime。 |

## 4. 数据与解释规则

### 4.1 文档发现

新登记项目默认自动发现：读取 `.workflow-system/PROJECT_PROFILE.yaml` 的 `paths.documentation_files` 和 `paths.workflow_home`，以文档中心、目录、需求索引、任务文档明确引用及已知 `related_docs` 元数据进行有界导航。可用时读取 `README.md`、`docs/README.md`、管理目录下的 `DOCUMENT_CATALOG.md`；管理目录没有声明时采用 `docs/workflow/` 的默认候选。仅提取登记与正文，不调用 Runtime 或执行脚本。

以上路径是默认候选，不是强制目录结构。分类优先采用文档中心的明确用途／栏目、目录分类或已知类型元数据；仅由标题／路径提示得到的分类标为建议，未知或冲突保留待分类。手动规则补充或覆盖分类，排除规则优先；高级设置可关闭自动发现，只使用手动范围。旧项目配置不静默扩大范围，可由用户开启自动发现后刷新。不遍历整个仓库推断用途，不把自定义 `requirements_files` 等兼容字段当成 vNext 必需标准。

登记核对展示路径、分类及依据、状态、替代声明、读取结果，来源可回到本快照原文。草案、模板、归档、废弃或已被替代的材料不作为现行需求／设计齐备的依据。未发现登记、分类未明、文件缺失／不可读与导航截断分别保留。目录约定或任务引用只证明已记录导航，不能证明覆盖全部用户需求、AI 已理解或已实现；用户需求完整性明确保持尚未确认，需对照原始需求核对。

通用发现支持普通文档的显式 Markdown 引用、已知 vNext 文档类型与项目相对路径引用，以及可用的根目录和管理目录任务文件。开启自动发现时，可在约定目录内只盘点文件元数据，将存在但未登记的文档独立展示、搜索并带入整理提示词，不自动认定用途或读取正文。目录范围可配置，默认 `docs`、`TASKS`；`records` 默认排除，可由用户显式允许。候选盘点、文件导航和登记来源列表的截断分别说明。示例占位路径不作为必需文件，简写有歧义时保持待核对。

### 4.2 状态与进度

仅提取明确的状态字段、清单、章节和任务引用。可以展示“已勾选 3/5 项”，但不得据此宣称“项目完成 60%”。

无法识别的字段或格式保留原文，并显示“未识别”或“未记录”。不同文档声明冲突时并列显示来源，不按修改时间擅自裁定。未发现关联，只表示“扫描范围内未发现显式关联”，不表示需求尚未实现。

### 4.3 关联与来源

优先识别 `Project documents` 等结构化引用、Markdown 链接和可唯一定位的任务编号。引用中有章节时尝试定位章节；无法定位时保留原始引用并提示。

普通链接和任务编号提及只建立“引用／提及”关系，不自动升级为“实现／完成／验证”关系。每项提取结果及关联均保留来源文件和位置，供用户核对。

引用目标不在扫描范围内时，只核对元数据，区分文件存在、路径不存在、已排除及尚未核对；不能仅因未收录就判定文件缺失。已终止、暂停、跳过等状态不得合并成“已完成”；无法可靠识别的状态保留原始声明。

### 4.4 快照与刷新

添加项目并确认范围后进行首次扫描。切换页面、查看详情和服务重启均不隐式扫描；重启后保留登记与配置，快照显示“尚未扫描”。

添加前的文档发现是有界只读预览，不发布项目快照。启用自动发现后，每次手动刷新重新读取 Profile、导航入口与正文，不把添加时的候选固化为文件清单；有效索引撤回的条目正常退出结果。登记入口损坏或不可读时，可重新读取上次快照由该入口发现的路径，标明入口无法核对；不复用旧正文或宣称本次登记完整。

更新扫描配置后提示“配置已变更，需刷新”；刷新前的旧快照继续显示它实际使用的范围与时间。刷新期间保留旧内容并标识扫描中，新快照就绪后整体切换；文档阅读和来源定位必须对应当前展示的快照。

本次扫描成功确认已删除或已排除的文档，不得继续作为当前结果展示；读取失败须保留错误，不能当作正常删除。部分成功与整体失败按验收标准处理。

### 4.5 文档整理辅助

扫描后提供可预览、复制的文档整理提示词，包含项目位置、当前登记、缺口和简短维护约定。用户在项目的 AI 会话中执行后，再回到 TraceLens 手动刷新。优先修复项目已有文档中心；无可用入口时按项目规范补建 `docs/README.md` 路径导航并经正常方式登记到 Profile。保留正文位置，不复制正文建立第二套权威文档，不直接手改生成目录或已确认 Runtime 材料。工具不调用 AI、不发送消息、不写被观察项目；提示词不能生成确认或完成结论。提示词记录达到输出限制时标明省略项。

### 4.6 标准产品通路与显式启用

PRODUCT 默认入口是 `.workflow-system/PRODUCT.yaml`，高级配置可选择一个其他 YAML 入口，不自动合并。新项目添加预览展示 managed/source 范围，用户勾选后启用；旧配置缺少 `product` 保持关闭，与 autoDiscover、includeRecords 独立。保存只改本工具配置，手动刷新后生效；maintenance paused 仍可读。未启用、入口缺失、排除、不可读、不支持版本、部分可用、有效空结果分别显示。

仅 managed_paths 枚举当前标准文档，不受通用三层导航限制，仍受相同全局文件／字节／安全预算。有效 PRODUCT 排除在通用导航之前生效，统一覆盖手动规则、候选盘点、来源及 adopted-plan 精确读取；缓存命中不能绕过排除。失败读取已经消耗的字节仍计入共享预算。source_paths 只许可按条目直接 SourceRef 有界读取 Markdown、YAML、JSON、TXT；capture_paths 不授予扫描或写入权限。历史／raw 不进入当前定义；精确 records 来源可读，不扫描 records 或重放 journal，不运行被观察项目 helper。有效 manifest 撤回文件后退出当前集合，入口损坏不恢复旧产品定义；整次刷新失败仍保留整份旧快照及时间。

v1/v2 按固定生产 Schema 只读解释，未知版本保留原文。根级 AST 二级标题对应条目，代码／引用／列表伪标题不产生条目，正文至下一根级二级标题；一文件多类型只保存一份原文。非法 YAML、不可解码输入保留文件级错误，不信任残缺对象；可安全定位的单项 Schema／章节错误隔离保留。重复当前 ID 不取最新文件获胜。条目片段保留完整原文件的引用式 Markdown 定义上下文；普通 Markdown 引用继续显示在既有依据列表，不提升为实现或验证关系。标题与原文绝对行号同快照，原始字节 SHA、需求定义 SHA 与 Git SHA 互不替代。

current 是当前业务范围，不是未完成；retired 不是完成；intent_state、工作项安排、任务文档状态、交付报告分维度展示。真实任务身份只从明确字段／支持的焦点声明取得；null 不回填，显示编号不猜身份。同文件焦点变化重核身份，多来源状态冲突并列。step_id 是任务内步骤，产品 plan_id 不等于 Runtime plan_ref。没有绑定只代表未记录关联。

assessment 仅由 requirement.assessment_id 选择，不选最新。旧 pass-reported、新 pending_sources、报告对象、覆盖与定义／原件核对同时可见；相同字节或定义不证明当前代码适用。inferred 必须保留理由来源，dismissed 有可发现入口，均不代表执行授权。讨论有关联不表示采纳，change 记录不证明所有正文已同步。

读取覆盖、结构可用、业务 inventory、来源核对、交付报告分别呈现，不以单一成功标记或任务关闭比率替代。两工作副本即使 project_id 相同也不合并，条目 ID 大小写保留；刷新后同身份移动可重定位，撤回或删除明确失效。

## 5. 界面与边界

设置六个项目入口：**概览、需求、规划、任务、文档、关联**，以及不依赖项目的 **vNext 使用说明**。

| 页面 | 主要使用效果 |
|---|---|
| 概览 | 首屏看清当前任务／步骤、文档声明的进展和待办、扫描时间与异常；缺少信息时明确提示。 |
| 需求 | 浏览九类标准条目、完整需求 scope 过滤、目标—需求—设计关系、全文与来源；坏条目仍可定位。 |
| 规划 | 单／多／无计划阅读，原顺序工作项、关联任务与修复；不推断串行、并行或完成率。 |
| 任务 | 列表与详情联动，查看目标、步骤、清单和问题，点击引用可进入文档对应位置。 |
| 文档 | 按类型浏览、查看章节目录与原文；能反查哪些任务或文档明确引用了它。 |
| 关联 | 展示选中任务或文档的局部关系，节点可点击、边能解释来源；不要求铺开全项目。 |
| vNext 使用说明 | 按业务场景查找 canonical skill、模式、可复制提示词、预期结果与边界；标明资料核对版本，不暗示项目当前状态。 |

采用克制、信息优先的工具界面，优先保证长标题、路径和正文可读。完成加载、空项目、未扫描、无匹配结果、部分失败和整体失败的交互。不得以营销首页、大量装饰性统计卡片或假数据看板替代实际功能。

首版仅提供本机、单用户、只读访问。项目文档不得被修改；允许写入本工具自己的项目配置。默认只监听回环地址，限制文件读取范围，Markdown 不执行脚本或内嵌组件。

不包含：文档编辑、任务执行或审批、vNext API／journal 消费、文件监听与实时推送、AI 推断、向量检索、Git 状态分析、远程协作及桌面安装包。首版不解析 PDF、Word 或任意二进制文档。

## 6. 验收与交付完成标准

1. 能添加至少两个项目并独立查看；重启后项目登记和配置仍存在。
2. 样例中的状态、任务、清单和显式引用能正确展示，并能回到对应原文位置。
3. 文档新增、修改、删除或扫描配置变化后，手动刷新能正确更新页面；仅浏览页面不会重新扫描或修改项目。
4. 单个文档缺失、解析失败、引用断裂或状态冲突，不影响其他可用内容展示；异常不得静默丢失。
5. 整体刷新失败时保留上次成功快照，并明确标记本次失败及旧快照时间；没有旧快照时展示错误，不伪装成空项目。
6. 不调用 vNext API、不执行项目脚本，不修改被观察项目，不将文档统计宣称为真实开发完成度。
7. 六个页面形成真实操作闭环：添加目录 → 自动发现已有文档入口 → 查看概览与登记缺口 → 打开任务 → 跳转引用章节 → 查看局部关系 → 复制整理提示词 → 修改样例文档／索引并刷新发现变化；不得用硬编码返回值代替扫描结果。
8. 交付可运行代码、依赖锁文件、README 和最小示例项目；README 写明环境要求、安装、开发、构建、生产启动、验证命令、配置位置及已支持／未支持的文档结构。构建后由一个本地服务提供完整界面和 API，不依赖开发服务器才能使用。
9. 使用说明页在无项目和已有快照时均可访问，覆盖 11 个 vNext canonical skills，搜索、筛选、提示词复制及小屏布局实际可用；打开说明页不触发扫描或项目写入。

**完成定义：** R1–R12 均有实际实现，上述验收有可复核的验证结果，类型检查、相关测试、构建及本地启动已执行。通过浏览器验证核心闭环和异常展示，不能只凭接口测试宣称界面完成。验证强度按实际风险确定，不要求为每条文字各建一项测试。

样例应包含正常引用、断裂引用、冲突声明和未知格式，样例数据与用户项目数据明确分开。有可用真实文档时优先用其只读副本核对；只有合成样例时说明覆盖范围，不宣称已验证真实 vNext 全版本兼容。环境受限或存在阻塞时交付已完成部分，并列明未运行、未通过及待确认项，不计作全部完成。
